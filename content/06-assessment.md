## 怎么验收

正式验收共 8 次，每名学生约 10–15 分钟，计入当日 3.5 小时。学生可查官方文档，但现场任务必须自己操作。课程视频、Git 提交数和截图数量都不单独计分。

每次小作业按 100 分打分：功能完成 40、可复现 25、理解与现场修改 25、记录质量 10。建议 ≥70 分且满足本次“必过项”才通过。导师可记“通过／待补／未演示”，不把“交过文件”写成“通过”。补验保留原记录，避免学生因一次错误放弃后续。

| 作业 | 日期 | 总评权重 | 核心产出 |
|---|---|---:|---|
| A1 Linux | D4 | 10% | 脚本、日志筛选、环境报告 |
| A2 Python／环境 | D8 | 10% | CSV 工具、Git 历史、环境复现 |
| A3 ML 基线 | D11 | 15% | 划分、基线、无泄漏评价 |
| A4 神经网络 | D15 | 15% | 训练／验证、checkpoint、独立推理 |
| A5 视觉 | D18 | 10% | 颜色定位、微型 CNN、失败分析 |
| A6 ROS 2 | D24 | 15% | Python 包、有反馈的到点控制 |
| A7 GNN／具身 | D26 | 10% | 图聚合、接口说明、平台条件判断 |
| A8 综合项目 | D30 | 15% | 固定协议评估、复现、答辩 |

结业建议：总评 ≥70 且 A1–A8 核心项全部通过。选做只写能力备注，不靠 GPU／硬件优势抬高必修分数。不能运行、错误的数据划分、无法解释主要代码，需要补验，不能被报告排版抵消。

## A1：Linux 科研工作目录

**任务**：在自己的 Linux 主目录新建独立项目，编写环境报告与日志汇总脚本。脚本生成 20 行日志，其中每第 5 行为 ERROR，提取并计数错误，打包结果。任意当前工作目录下都能按 README 运行，不依赖人工预先创建临时输出。

**提交**：`linux/env_report.sh`、`linux/run_demo.sh`、完整日志、恰好 4 行错误的文件、汇总文本、README、一个排错记录。运行脚本本身就能重新生成这些输出。

**必过项**：能从终端启动；结果计数正确；能解释路径与权限；重复运行不会把旧日志追加成错误结果。无需完全脱稿记命令。

**现场变化**：导师切换工作目录，或移除执行位，要求学生识别并修复。提问：“`>` 和 `>>` 会怎样影响这次结果？为什么不对所有文件 chmod 777？”

**选做**：支持输入日志路径，增加 `--help`。失败者在 D7 前补最小脚本，不先继续安装更多软件。

## A2：一个能交给同学复用的小工具

**任务**：编写 CSV 汇总工具，正常／空／坏值三类输入都能清楚处理；用 NumPy 验证统计结果；保存图；管理一次 Git 分支修改；记录并复现 CPU 环境。

**提交**：脚本、3 个小输入、期望／实际输出、至少 3 个有意义的 commit、环境完整导出与 pip 版本文件、解释器路径、自检输出、重建步骤和结果。

**必过项**：不依赖 Notebook 隐藏变量；输入错误时给出可理解提示；能指出正在使用哪个 Python；同类系统新建环境后成功运行，或标注环境复验尚未完成而非提前通过。

**现场变化**：更换输入文件并改变输出路径；提问：“Windows 上装了 Anaconda，为什么 WSL 的 Python 仍可能找不到包？`from-history` 能记录所有 pip 依赖吗？”

**选做**：写一个小型自动检查脚本比较已知均值。Python 不熟者优先补函数／文件操作。

## A3：一份可信的机器学习结果

**任务**：digits 固定 train/val/test 划分；多数类与逻辑回归基线；只在验证集选最多 2 个参数；最终报告一次测试结果。

**提交**：切分索引、代码、参数、随机种子、两种模型的指标、混淆矩阵、5 个错误样例，说明预处理 fit 在哪里发生。

**必过项**：训练／验证／测试样本不交叉；预处理没有读取验证／测试统计量；指标来自真实运行；能解释基线用途。准确率 0.90 仅作排查参考。

**现场变化**：导师指出一段“全量 fit scaler”伪代码，让学生改正确；提问：“能否根据测试集选 C？混淆矩阵哪两个数字最容易混？”

**选做**：加决策树，只比较同一划分。泄漏问题先修后验，不用再看大量算法视频。

## A4：完成一个神经网络的生命周期

**任务**：digits 两层 MLP，保存逐轮训练／验证指标；两种学习率做单因素对照；按验证结果选 checkpoint；新进程加载、推理、最终测试。

**提交**：train/predict 入口、配置、日志 CSV、两次曲线、环境、checkpoint 获取位置、单样本结果与一页分析。权重可作为提交附件，不强制进入 Git。

**必过项**：训练循环确实更新参数；输出／标签 shape 正确；验证不参与反向传播；独立加载成功；模型选择未使用测试集。

**现场变化**：把 batch size 改小并跑 2 个 batch；提问：“少了 zero_grad 会怎样？eval 与 no_grad 有何不同？为什么只保存一张 loss 图还不够复现？”

**选做**：第二个种子或 Fashion-MNIST，二选一。

## A5：视觉输入可以被解释

**任务**：合成圆点图中心定位；增加空图、暗光、遮挡等失败例；同一 digits 划分训练微型 CNN。

**提交**：原图／标记图、中心 CSV、保留测试的定位误差与误检、CNN shape 表、参数量、曲线、与 MLP 的同协议比较、3 个失败说明。

**必过项**：新输入可运行；无目标时显式无效；解释 BGR／RGB 与 NCHW；CNN 可保存加载；没有把像素直接当真实米坐标。无需 CNN 一定超过 MLP。

**现场变化**：换目标颜色或空白图；提问：“阈值为什么不泛化到所有光照？像素中心到机械臂末端动作还缺什么？”

**选做**：只在训练集加入图像增强，比较保留集结果。

## A6：机器人软件最小闭环

**任务**：写 ROS 2 Python 包，订阅位姿，发布速度，完成 3 个固定目标；目标位置和速度上限可配置；做一次话题录制与分析。

**提交**：`ros_ws/src/`、launch、README、节点／话题示意、3 次轨迹与结果、rosbag 的存放说明或元信息、过期输入停止证据。

**必过项**：源码可构建并启动；用实时位姿反馈而非定时盲发速度；到点停止；无新位姿超过 1 秒后在一个控制周期内发零速度。只会键盘遥控不算通过。

**现场变化**：改目标，暂停位姿来源或在无图形路线暂停仿真节点；提问：“topic 与 service 的用途有什么不同？为什么先 source？角度误差跨 ±π 怎么处理？”

**选做**：参数动态修改或 tf2 小例子。WSL 跨机问题不在核心验收范围。

## A7：读懂具身项目，而不是只会安装

**任务**：实现 4 节点图的聚合与删边变化；整理一页具身数据／策略接口；提交 Isaac Sim 版本条件清单。

**提交**：手算、代码、两种边结构的结果、shape 解释；observation/action/episode 表；部署条件表；明确“实际运行／文档了解／尚未验证”。

**必过项**：聚合结果正确；知道固定聚合不是训练好的 GNN；区分监督学习／模仿学习／强化学习；知道动作单位与时间对齐；能判断本机不满足某平台要求时采用什么替代路线。没有工作站不扣分。

**现场变化**：修改一个节点特征预测哪些节点会受影响；提问：“一层和两层聚合影响范围有何区别？为什么按随机帧切机器人轨迹会有泄漏风险？”

**选做**：PyG 例子或 Isaac Sim 实机演示，二选一。

## A8：可复现的综合小项目

**任务**：按机器人模块定义完成观测处理→控制→二维仿真的系统；10 个固定正常场景与 2 项失效测试；同学复跑；完成答辩与毕设衔接计划。

**提交**：完整仓库与 commit、环境记录、启动命令、固定场景配置、逐次 CSV、成功率／耗时／误差汇总、故障结果、2 分钟录屏或现场演示、2–3 页报告。

**必过项**：另一位同学按 README 能启动；正常场景 ≥8/10、故障测试 2/2；阐明适用范围和仿真局限；能现场改一个目标或阈值；结果可追溯。网络或包下载阻碍复跑时记录具体阻塞，不能直接认定复现成功。

**答辩结构**：5 分钟目标／方法／结果，5 分钟运行，5 分钟修改／问答。提问：“如果换成真实相机和机械臂，需要改哪些接口、检查哪些单位？如果控制器替换成学习策略，评价协议如何保留？”

**补验**：保留原始失败 CSV，修改后重新运行整套固定场景，报告版本差异；不能只重跑失败的场景后混合成一份成绩。

## 日常微验收

D1 环境可进入；D3 日志过滤；D6 shape 与 Git diff；D10 划分解释；D13 保存加载；D16 无目标处理；D20 话题类型；D22 节点构建。每次 5–10 分钟，可同伴检查；正式验收仍由导师抽查。导师可随机让学生解释两行代码，定位“能运行但不理解”的问题。
