## M6：ROS 2 最小闭环（D19–D24，17.5 小时）

先修：Linux、Python、命令行运行与基本调试。ROS 2 是机器人软件通信与组织框架；本阶段核心是节点、消息、坐标和反馈，不要求完整 SLAM、Nav2、MoveIt 2 或机械臂动力学。

### 环境路线

使用 Ubuntu 24.04 + ROS 2 Jazzy。按 R11 官方页完成 locale、软件源、开发工具和 desktop 安装。不要只复制 `apt install` 而漏掉前面的软件源配置。旧视频里的 Foxy／Humble 软件源和安装命令不直接复制到 Jazzy。

安装后在两个已退出 Conda 的 Ubuntu 终端分别运行：

```bash
source /opt/ros/jazzy/setup.bash
ros2 run demo_nodes_cpp talker
```

```bash
source /opt/ros/jazzy/setup.bash
ros2 run demo_nodes_py listener
```

能收到消息后再做 R12。所有课程节点先在同一台机器上运行；WSL 跨机 DDS 发现、USB 转发和机器人局域网接入不作为初学必过项。

### A6 控制器的具体规格

订阅 turtlesim 的 pose，计算当前位置到目标的距离 `d` 与期望朝向 `atan2(dy,dx)`。朝向误差归一化到 `[-π,π]`；误差很大时先转向，再前进。建议角速度上限 1 rad/s、线速度上限 1 仿真单位/s，到目标 0.2 单位内停止。这些只是本课程仿真参数，不是真机参数。

在三个固定任务上测试：初始位姿均为 `(5.5,5.5,0)`，目标依次 `(8,5.5)`、`(5.5,8)`、`(3,3)`；每次先复位。订阅位姿后才允许运动；接收时间超过 1 秒无更新时发零速度；完成后持续发零速度。说明 turtlesim 的长度是仿真坐标单位，迁移到实际机器人时才按对应接口规定使用米。

### 图形运行不了的同等路线

用系统 Python 和 rclpy 写一个无图形 `sim2d` 节点，状态为 x、y、yaw，按固定 `dt=0.05` 积分：`x += v*cos(yaw)*dt`，`y += v*sin(yaw)*dt`，`yaw += w*dt`，并归一化角度。订阅 `geometry_msgs/Twist` 的 `/cmd_vel`，发布 `geometry_msgs/Pose2D` 的 `/pose2d`；Pose2D 仅用作本课程简单二维练习接口。增加复位能力，收到速度指令超时 1 秒自行归零。

该节点预计占用 D20 的动手时间；卡住时导师可发半成品骨架，学生完成积分和超时逻辑。将轨迹保存 CSV 并绘图，仍按相同闭环标准验收。它不模拟碰撞、惯性、接触和真实传感器误差，不能作为真机动力学验证。

## M7：GNN 与具身学习接口（D25–D26，7 小时）

### D25：人人必做的最小图消息传递

阅读 R14 的图数据、节点特征、边与 message passing 概念。核心练习**不安装 PyG**，直接用 NumPy 或 PyTorch，减少编译扩展依赖。

图为无向链 `0—1—2—3`，节点标量特征 `[1,2,4,8]`。加入自环，按每个节点“自身＋邻居”取均值：`H' = D^(-1)(A+I)H`，D 是含自环后的度矩阵。手算结果应为 `[1.5, 7/3, 14/3, 6]`。删除边 `1—2` 后重算，预期为 `[1.5,1.5,6,6]`。通过代码验证；再将特征扩成二维，解释矩阵 shape。

说明这只是固定的一层聚合算子，没有可学习参数，**尚不是训练好的 GNN**。进一步写出 `H' = σ(D^(-1)(A+I)HW)`，指出 W 如何接受梯度。能举出机器人关节图、场景物体关系图之一，说明节点、边和特征分别代表什么；也要说明并非所有具身模型都必须用 GNN。

选做：按 R14 安装 PyG，完成一个官方小例子；不把安装 PyG、跑 Cora 或通读 CS224W 作为核心合格线。需要图学习的毕设，在基础月之后单独补 1–2 周。

### D26：把“模型”放进机器人系统

R15 选读模仿学习入门，R16／R17 选看仓库结构与输入输出接口。用自己的话说明：

- observation：图像、关节／位姿等可用观测，含时间和单位约定。
- action：机器人执行接口所需的量，可能是关节位置、速度或末端位姿增量，不能混用。
- episode：一次完整交互轨迹；时序数据的训练／验证／测试应按 episode 或场景划分，不能随意随机拆相邻帧。
- policy：把观测映射为动作的规则或学习模型；行为克隆用示范动作作监督，强化学习利用奖励与交互。
- VLA：视觉、语言和动作之间的建模方向；本月理解接口，不要求训练大型模型。

提交一张文字框图：传感器／回放 → 预处理 → 策略 → 动作转换／限幅 → 仿真或机器人 → 新观测；逐项写明 shape、频率、单位及无效输入的处理。说明一个离线预测准确率高的策略为何仍可能闭环失败。

### Isaac Sim 该学到哪里

所有学生先读 R18 的版本化硬件要求；填写版本、OS、GPU 型号与显存、内存、磁盘、驱动、数据下载条件和兼容性检查结果。没有条件的结论可以是“本机不部署，使用实验室演示／后续预约工作站”，不扣分。

有预配置工作站时，导师展示：载入机器人／场景、播放暂停、查看关节、读取一次传感器输出、解释与 ROS 2 Bridge 的关系。没有工作站时，通过官方入门资料梳理同一流程，明确没有实际运行。**不要求在 WSL2 内部署 Isaac Sim，也不把其他 GPU 可训练 PyTorch 等同于满足 Isaac Sim 要求。**

## M8：结业项目——可复现的二维到点闭环

核心路线重用 A6 控制器，新增独立观测处理节点、统一接口和实验日志；不要在最后三天从零写完整导航系统。题目是基础能力集成，最终系统可以是规则控制器，学习策略替换为选做。

### 核心数据流与实现合同

`turtlesim / sim2d 位姿 → 观测节点 → 控制节点 → 速度指令 → 仿真`

观测节点订阅位姿并与当前目标相减，发布相对目标 `dx,dy`、朝向误差和有效性；本月可使用 `std_msgs/Float64MultiArray`，约定 `[dx,dy,heading_error,valid]` 并在 README 写清顺序和单位。更规范的自定义接口是选做。控制节点用接收时间检查新鲜度，输入缺失或 valid=0 时输出零速度。观测节点本身也要检测上游位姿是否过期，不能不断重发过期的“有效观测”。

建议频率 20 Hz，和 A6 使用相同的速度上限及到达阈值。启动时未收到有效观测保持停止；换目标清除上次成功状态；CSV 记录 timestamp、pose、target、distance、command、valid。用 launch 文件启动，README 至少写出准备、运行、测试、停止四条命令。

### 固定测试协议

每轮最长 30 秒，以运行时的仿真时间计；在正常实时 turtlesim 中可记录单调时钟，同时声明计时方式。每轮重新设定初始位姿和目标；达到阈值 ≤0.2 且持续停止 1 秒计成功。

| 编号 | 初始 (x,y,yaw) | 目标 (x,y) | 目的 |
|---|---|---|---|
| T1 | (5.5,5.5,0) | (8,5.5) | 直行 |
| T2 | (5.5,5.5,0) | (5.5,8) | 转向 |
| T3 | (5.5,5.5,0) | (3,3) | 后侧目标 |
| T4 | (3,3,1.57) | (8,8) | 较长距离 |
| T5 | (8,3,3.14) | (3,8) | 斜向 |
| T6 | (8,8,-1.57) | (3,3) | 另一象限 |
| T7 | (3,8,0) | (8,3) | 朝向调整 |
| T8 | (5.5,5.5,3.14) | (5.5,5.5) | 初始已到达 |
| T9 | (4,4,-3.10) | (3,4.05) | 角度跨 ±π |
| T10 | (6,6,1.0) | (6.3,6.3) | 近距离 |

另外做 2 项故障测试，不计入正常成功率分母：运行中暂停观测节点，检查最后有效消息 1 秒后在一个控制周期内发零速度；启动时无观测，检查始终停止。核心通过建议为正常场景 ≥8/10，故障测试 2/2，低于 8/10 可修正后复验但保留前一版结果。记录真实结果，不能先填写“预期成功”。

### 选做分支：每人只选一项

1. **视觉闭环**：在课程定义的合成二维画布中生成目标图，使用 A5 颜色定位；明确像素到仿真坐标映射，不冒充真实相机标定。
2. **行为克隆**：采集规则控制器的短轨迹，以相对位置／朝向为输入拟合小 MLP；按轨迹划分；比较规则控制与学习策略的闭环成功率，不能只报告动作 MSE。
3. **GNN**：构造物体关系图，完成一个可解释的小预测任务，展示去掉边后的变化。
4. **Isaac Sim**：仅在已有工作站上替换仿真端，提交实际版本与运行证据，接口不兼容时列出差异，不强行宣称迁移完成。

## 从基础月到实际毕设

结业报告必须列出下一阶段缺口：目标模型／仓库／commit，机器人的动作接口，传感器与数据格式，算力／显存，训练还是推理，评估任务，以及谁提供设备与示范数据。若最终目标为 π 系列／其他 VLA，请先由导师确认具体名称，再按其官方版本要求搭环境；不把这里的 Python 3.11 基础环境直接复制成全部具身项目环境。

真机衔接顺序：离线数据检查 → 仿真／回放接口验证 → 实验室人员确认动作单位、限位、急停和通信中断处理 → 在场监督下低速试验。基础课仿真参数不得直接当作机械臂或移动底盘参数。真实部署由实验室既有规范和设备负责人安排。
