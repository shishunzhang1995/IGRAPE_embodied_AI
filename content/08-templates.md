# 学生提交模板

[首页](README.md) · [作业标准](06-assessment.md)

以下模板直接复制到自己的仓库。示例占位符必须替换为真实内容；尚未运行写“未运行”，没有结果不要填推测值。

## 3. 每个作业的 README

```text
作业编号／姓名：
目标：一句话说明输入、输出和要验证的问题。
环境：OS、Python、关键包版本、CPU／GPU；版本文件路径。
代码版本：commit hash；参考代码／教程链接。
数据：来源、样本数、切分方式；无需数据时写不适用。
准备命令：从新终端开始。
运行命令：训练／评估／推理或节点启动，分别列出。
预期输出的位置与格式：不填写未测得的成绩。
实际结果：原始日志路径、指标、耗时、图表。
对照：只改变了什么，其余如何保持一致。
解释：为什么得到这些结果，证据是什么。
失败与限制：至少一个失败或不确定性。
重现记录：谁在什么环境上复跑，是否成功，差异是什么。
辅助使用记录：AI／同伴／参考仓库帮助了哪些部分。
```

## 7. 综合项目报告（2–3 页）

1. **任务与边界**：仿真平台、输入／输出、成功定义；说明没有模拟的真实因素。
2. **系统与接口**：节点图，消息字段、坐标系、单位、频率、超时；关键代码位置。
3. **复现说明**：环境、commit、准备和启动命令、固定场景配置、输出位置。
4. **结果**：10 场景逐条结果；成功率、耗时与终点误差；2 项故障测试；保留原始 CSV。
5. **解释与失败**：至少 2 个失败或边界案例；若全部成功，构造扰动测试并记录，不虚构失败。
6. **毕设衔接**：目标模型／平台，缺失知识，算力／数据／设备依赖，下一两周可验收目标。
